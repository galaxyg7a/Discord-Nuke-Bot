About the Bot

Last Stand is a private Discord bot built exclusively to stress-test a custom anti-raid system on a private test server. Built by Jean (Lorenzo).

Tech Stack

🐍
Python 3.12
Core runtime. All bot logic is Python.
🤖
discord.py 2.3+
Cog-based architecture. Slash commands via app_commands, prefix commands via commands.ext.
⚡
asyncio
asyncio.gather + asyncio.Semaphore for all concurrent operations. Semaphore(2) for channel creation, Semaphore(25) for spam.
🔥
requests (raw HTTP)
100 daemon threads each firing raw requests directly to Discord REST API, bypassing discord.py's rate limit buckets entirely.
🚀
Railway + Docker
Deployed via Dockerfile (Python 3.12-slim). Auto-redeploys on every Git push. Replit is editor only — bot never runs locally.
🛡
BypassEngine
Custom per-route 429 isolation, adaptive retry, full-jitter exponential backoff, fingerprint rotation.

Core Architecture

01
BotState Singleton (utils/state.py)
All cogs share one bot_state instance. Holds the stop_event (asyncio.Event — set by /stop, checked in every loop), active_simulation (prevents double-starts), running_tasks (set of active asyncio.Tasks), and references to the BypassEngine and RateController.
02
HttpQueue (utils/http_queue.py) — c-realV2 Port
100 daemon threads pull from an unbounded Python Queue. Each thread fires raw requests calls directly to Discord's REST API with the bot token. On 429: sleeps min(retry_after, 5s) then always requeues — requests are never silently dropped. /stop calls queue.clear() to instantly drain pending operations.
03
BypassEngine (utils/bypass.py)
Handles all discord.py API calls (channel creates, server edits). Per-route 429 isolation means a ban rate limit doesn't pause webhook sends. Uses adaptive retry with full-jitter exponential backoff. FingerprintRotator varies content to avoid pattern detection.
04
RateController (utils/rate_control.py)
Intensity 1–10 mapped to delays and burst sizes. Shared across all cogs. Adjustable live during a running simulation with /setratelimit — no restart needed.
05
Cog Architecture
Commands split across four cogs: raid.py (full destruction engine), ban.py (mass ban/kick/unban), spam.py (webhook flood), control.py (stop, status, nuke, timeoutall). All loaded by bot.py on startup.

How /raid Works

All six phases launch concurrently from a single asyncio.create_task call. Nothing is sequential.

Phase 1
Rename + Lock Server
Renames the server to RAIDED BY JEAN(LORENZO) FROM LAST STAND and removes all @everyone permissions.
Phase 2
Wipe Server Assets
Removes server icon, banner, description, and stickers. Sets description to the raid tag and link.
Phase 3
Wipe All Emojis
Queues DELETE requests for every custom emoji in the server via the 100-thread HTTP queue.
Phase 4
Channel Nuke + Flood Loop
Queues DELETE for all existing channels (protected ls-control hub is skipped). Waits, then creates 300 flood channels via discord.py (Semaphore(2), 2 channels/sec Discord limit), immediately spawning webhook spam on each. Loops until /stop.
Phase 5
Role Flood
POSTs 200 new roles named with the raid tag simultaneously via the HTTP queue.
Phase 6
Member Ops
Kicks, bans, timeouts (28 days), and sets nicknames for all members simultaneously via the HTTP queue. Respects role hierarchy — only targets members whose top role is below the bot's.

Discord Requirements

Both of these Privileged Gateway Intents MUST be enabled in the Discord Developer Portal (Bot → Privileged Gateway Intents):
  • Server Members Intent
  • Message Content Intent
Without Server Members Intent, guild.members returns an empty list and all member operations silently affect no one.

⚠️ Strict Rules

  • 🚫 Never run the bot inside Replit — no workflows, no python bot.py, no local execution of any kind.
  • 🚫 Never create pnpm-workspace.yaml — this breaks Railway by spawning phantom workspace services.
  • 🚫 Do not touch railway.json, .dockerignore, tsconfig.json, or src/index.ts.
  • ⚠️ Channel creation is capped at ~2/sec by Discord. BATCH=2, BATCH_PAUSE=2.0 — never increase BATCH or decrease BATCH_PAUSE or creates will fail silently.
  • ⚠️ Always call await guild.chunk(cache=True) before using guild.members. Without it the member list is empty or incomplete.
